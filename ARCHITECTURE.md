# Architecture

Just Us is a SwiftUI app for iOS 17. English is the development language. User-facing copy lives in `L10n` and `Localizable.xcstrings`. Views use leading and trailing edges.

The domain (`Schedule`, `Recommendation`, `PlannerTurn`, `TogetherStreak`, `PushPolicy`, `RitualPrivacy`) mirrors the web rules: Thursday math in `Asia/Jerusalem`, three home nights then one out, and a sealed plan for the partner. The next planner is the other member after the last completed or scheduled night, ordered by scheduled time and then created time. Weeks start on Sunday in the couple's time zone. One skipped week in a calendar month keeps the weeks-in-a-row count alive and does not add to it. Two skipped weeks in a row end it, as does a second skip that month, a week with no night, or a run whose newest week is older than last week. `017_planner_turn.sql` assigns that planner on a new draft. It is applied live on 2026-11-16 as `20261116024327`. Execute on its functions is revoked from `anon` and `authenticated`, live as `planner_turn_revoke`. Do not re-apply it. Idea titles on iOS come from the bundled English catalog, keyed by the same ids as the web.

`DateBackend` has two implementations. `-uitest` and screenshots use `FakeBackend`. A normal launch uses `LiveBackend` and supabase-swift 2.55.6. The live client calls the existing RPCs (`create_couple`, `redeem_couple_invite`, `complete_date`, `ensure_active_draft`, `leave_couple`) and reads the same tables as the web. `leave_couple` is live. The replacement in `supabase/proposed/003_memory_photo_and_close.sql` was applied on 2026-11-15. Do not re-apply it. It closes the whole couple when either person unlinks, keeps both logins, tells the other person on their next launch, and returns the couple id it closed. `004_delete_my_account.sql` was applied on 2026-11-15. Do not re-apply it. Deleting an account closes every couple the person still touches, including one they already left, and removes their login. The other person's login stays. Photos for a leave are removed afterward by live `delete-couple-photos` v3, deployed from `main` at `a12f1d1` with `verify_jwt` on, only for those closed ids, and only through the Storage API. A failed call still finishes the leave on the phone. Account deletion does not call the function, because that login is already gone. The next launch retries a leave, and `justus-photo-sweep` retries rows whose login is already gone. SQL does not delete `storage.objects`. The iOS app calls `send-push` after a mood, a saved plan, a redeemed invite, and a chat message. Weekly reminders and invite nudges are not sent by the client. Chat uses CryptoKit Curve25519 and ChaChaPoly. The private key stays in the Keychain. The server stores public keys and ciphertext only. `015_partner_chat.sql` is applied live on 2026-11-16 as migration `partner_chat`. `015b_chat_messages_realtime.sql` adds `chat_messages` to `supabase_realtime` and is applied live as `chat_messages_realtime`. `016_chat_hardening.sql` is not applied. Apply it once. It requires the sender key to already be published, forces `created_at` to now, caps a sender at 30 messages a minute and 3 device keys, and deletes device keys when someone leaves or deletes their account.

Push registration writes `device_tokens`. Live `send-push` is v6, deployed on 2026-11-16 with the content of `5013075` (the same content as `7872d1e`) and `verify_jwt` on. The source is `supabase/proposed/functions/send-push`. It does not defer a push between 22:00 and 08:00. `a12f1d1` is v3 and is the rollback source. The daily cap, the six-hour dedupe, and the invite nudge windows stay. Secret names are in `docs/supabase-apple-and-apns.md`. The values are not in this repository.

Sign in with Apple hashes the nonce for the Apple request and sends the raw nonce to Supabase. In UI tests the system sheet is skipped.

Analytics and crash reports go to `os.Logger`. There is no third-party SDK.
